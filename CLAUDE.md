# Lendo — rules for working in this repo

- Cloudflare Workers + Hono + TypeScript, server-rendered Hono JSX. No framework migration without asking.
- Data: D1 via `c.env.DB.prepare(...).bind(...)` with parameters — never string-interpolate user input into SQL. Schema changes = new file in `migrations/` (never edit an applied migration).
- Photos: R2 only; keys `listingId/…` and `rentals/rentalId/…`. Serve via `/p/:key`.
- Auth: phone + texted code, session cookie `lendo_s`. Every route that reads or changes a user's data must check ownership (`owner_id === u.id` / party of rental). `requireUser` only checks login, not ownership.
- Money: all amounts in integer cents. Customer pays rent − credit + sales tax (NYC 8.875%, Iowa City 7%; `src/lib/money.ts`). Fee = 15% × (rent + tax), taken from the owner: owner gets rent − fee (`payout_cents`; old rows without it: rent). Lendo absorbs credits and remits tax. Minimum (Scott, 11/24): daily prices go down to $1, every rental charges at least $5 rent (`MIN_RENT_CENTS`, in `rentFor`); "$5 min" shows on the map hover and item page, not on pins. Stripe flow is hold → capture on YES → release on NO/expire. Deposit hold (Scott, 11/24): every rental, for the item's value, set by AI not the owner (`listings.value_cents`, `src/lib/value.ts`; valued by the cron about an hour after listing, never in the request path: no value yet → instant estimate from the daily price; owner can ask early or appeal once on the edit page) → `rentals.deposit_cents` at request, card saved at every checkout, hold placed on pickup day (owner sees "OK to hand over"), renewed every 6 days while out or while a claim is open, released when the owner taps "All good" or 24h after return (`rentals.ts` allGood/holdDeposit/depositsDue), captured only by a final AI ruling. Problems (`src/lib/claims.ts`, `/r/:id/claim`): owner claim → customer response → owner reply → customer last word (24h each) → AI ruling → both OK or one second look → final → `collectAward` from the hold + `payClaim` to the owner (no fee). Bank disputes: `onDispute` puts the evidence file on the Stripe dispute; Lendo covers the owner up to `settings.guarantee_cap_cents` (`/admin/claims`). Fraud guards (Scott, 11/24): every claim payout waits for a FaceTime call with the owner, then a person releases it at `/admin/claims` (`claims.payout_ok`, `releasePayout`); a hold over $500 (`HIGH_CENTS`) needs 2+ photos of the owner's own item, none a standard web photo, else the hold stops at $500 (`holdFor`), and needs the handover photo; after valuation the owner gets one combined nudge text for all their items, at most one a day (`nudgeOwners`; never one text per item), for real photos (worth over $500) and for what's wrong with it when the grade isn't A (`listings.issues`, shown to customers, given to the AI for value and rulings); the guarantee cap ($250) is in the Terms only, never in marketing or texts, and applies only if the hold was on the card at handover. The judge prompt (`RULES` in claims.ts) is policy: change it only when Scott asks. Changes to `src/lib/stripe.ts` or `src/lib/rentals.ts` need a second review pass for state-machine and refund correctness.
- Logging: every state change, money movement, webhook, login, listing change, admin action and error goes to the `events` table via `logEvent`/`logErr` (`src/lib/log.ts`); never delete rows from it. Admin views: `/admin` (dashboard, log, rentals, users, texts, searches, errors, CSV). Admin access: owner = `ADMIN_PHONES`; owner grants `view` (GET only) or `full` (all but /admin/access) at `/admin/access` (`users.admin_role`).
- Texts: all outbound texts go through `textUser` (logs to `outbound_texts`, respects STOP and `users.sms_ok`). Keywords handled in `src/routes/webhooks.ts`. Texting is primary; email (`src/lib/email.ts`, Resend) is the backup, never both unless a text got no response — except rental requests to the owner, which are always emailed at the same time as the text (`emailRequest`, Scott 11/24). Emails: no box/card, fluid ≤480px, same timeline-rail steps as the rental page. Dates are numeric everywhere ("Sat 11/28", `fmtDay`). Rules (Scott, 11/24): the user texts first (login page leads with "Text OK to Lendo", code form below as backup); each person has an allowance of texts in a row (`textAllowance`: Blooio tiers 3/4/6/8, Linq 6) that a written reply or a tapback resets (`recordTap`); decisions say "reply YES or NO", other texts ask for a 👍 only on the last allowed text (`KEEP_ASK`); past the allowance, rental/money/pickup/chat texts go by SMS line or email right away, nudges/alerts just wait in the web inbox; an unanswered request is emailed after 15 min (pickup today/tomorrow) or 2h (`src/lib/escalate.ts`). Phone buttons for YES/NO/I'm here are `sms:` links (`smsHref`, YES/NO carry the rental's last 4 chars). Email is required, asked on the welcome screen (`users.email`). Logged-out Rent on phones is a text too ("Rent <item> 11/27-11/29 · ref <id>" → `rentAsk` in webhooks.ts → login link that lands on the item with the days picked; `loginLink(env, phone, next)`). Terms: "By continuing you agree…" under the Text OK button and in the first welcome text.
- Copy voice: platform/tool voice — functional, not personified, no "we're so excited". No trailing periods in texts/UI lines (occasional "!" ok). Persuasive but not crass: mix community + money, don't lead with money. Name the neighborhood ("12 Northside neighbors…"); "neighbors" fine, never a vague "your neighbors". Now and then invite spreading it ("got one, or know someone who might?"). Never "gathering dust"-style cutesy lines.
- Terms: "owner" (lists, gets paid) and "customer" (rents, pays). Never "renter" in copy or new code names. Customers "rent", owners "list". Fee is "15% fee (will stay low)", paid by the owner out of the rent, charged from day one; customers never see a fee line; a free rental (owner waived) has no fee or tax.
- Questions one at a time (Scott, 11/24): no long forms. `public/steps.js` + `form.qs` (`data-mode="steps"` welcome: name → email → photo → home; `data-mode="menu"` profile: chunky rows, one opens at a time). Home = where someone's things are kept (`users.lat/lng`, set by `setUserWhere`); listing away from home asks "Where are these kept?" Home / Right here / Somewhere else (`needWhere` in list.js) so items never get pinned at an office. Names: ask first and last, others see first name + last initial (`shortName`). An owner viewing their own item sees the customer page with the rent parts greyed (`.own-off`) and one Edit button.
- Design minimal (Scott, 11/23): no dotted/dashed borders, no decorative number badges or alternating filled/outline styles, plain labels (e.g. "Condition", not "What shape is it in?")
- Brand: cream `#F5F3EE`, ink `#1E3A2B`, orange `#FF4F00`, Helvetica Neue. Logo = the outline hand (orange line `#FF4F00`, no fill color, thumb on the right, short wrist) in its L + "Lendo" in ink, not the 👋 emoji (favicon still 👋 for now). The hand appears ONLY in the logo spot; every gesture plays there: `hand()` in `src/lib/hand.ts` (`handStill()` for flyers/share picture), poses + keyframes in `public/app.css` (`.lh`), `public/hand.js` → `lendoHand('wave'|'shrug'|'nod'|'five'|'fist')` or `lendoHand(1..5)`; a page can ask with `<i hidden data-lh="nod">`. Moments: every page load plays an intro that ends in the L: 60% wave, 20% the L, 20% one fun/small gesture at random (heavy metal, hang loose, jazz hands, snap, drum, count, thumbs up, peace, OK, fingers crossed, so-so, nod; `FUN` in hand.js); the first homepage visit always waves; shrug = search finds nothing nearby; nod = listing posted / edit or price saved; high five = pickup confirmed; fist bump = rental request sent; fingers 1–5 when that number is the context (days picked on an item, stars tapped, 1–5 search results, 2–5 items posted). Gestures play 3 times then return to the L; never loop; nothing moves under reduce motion. Tokens in `public/app.css`. Design is always chunky, easy, simple, minimal: chunky icons (stroke ≥3, round caps, shared in `src/lib/icons.ts`), never thin glyphs/arrows.
- Verify: `npm run typecheck`, then `npm run dev` + walk the flow (list → rent → YES via `/webhooks/blooio` → pickup → return → rate).
- Item names/descriptions: name the brand (+ model) when visible AND it matters to a customer (electronics, cameras, power tools, appliances, audio, bikes, fitness, baby gear, designer fashion, outdoor brands); leave it out for commodity items (folding chairs, ladders, hammers, sleds). Never guess a brand. Descriptions = 1-2 lines of checkable facts (model, key spec, what's included, visible condition), no filler. Rules live in `src/lib/identify.ts`.
