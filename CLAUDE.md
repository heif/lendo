# Lendo — rules for working in this repo

- Cloudflare Workers + Hono + TypeScript, server-rendered Hono JSX. No framework migration without asking.
- Data: D1 via `c.env.DB.prepare(...).bind(...)` with parameters — never string-interpolate user input into SQL. Schema changes = new file in `migrations/` (never edit an applied migration).
- Photos: R2 only; keys `listingId/…` and `rentals/rentalId/…`. Serve via `/p/:key`.
- Auth: phone + texted code, session cookie `lendo_s`. Every route that reads or changes a user's data must check ownership (`owner_id === u.id` / party of rental). `requireUser` only checks login, not ownership.
- Money: all amounts in integer cents. Customer pays rent − credit + sales tax (NYC 8.875%, Iowa City 7%; `src/lib/money.ts`). Fee = 15% × (rent + tax), taken from the owner: owner gets rent − fee (`payout_cents`; old rows without it: rent). Lendo absorbs credits and remits tax. Stripe flow is hold → capture on YES → release on NO/expire. Changes to `src/lib/stripe.ts` or `src/lib/rentals.ts` need a second review pass for state-machine and refund correctness.
- Logging: every state change, money movement, webhook, login, listing change, admin action and error goes to the `events` table via `logEvent`/`logErr` (`src/lib/log.ts`); never delete rows from it. Admin views: `/admin` (dashboard, log, rentals, users, texts, searches, errors, CSV). Admin access: owner = `ADMIN_PHONES`; owner grants `view` (GET only) or `full` (all but /admin/access) at `/admin/access` (`users.admin_role`).
- Texts: all outbound texts go through `textUser` (logs to `outbound_texts`, respects STOP). Keywords handled in `src/routes/webhooks.ts`.
- Copy voice: platform/tool voice — functional, not personified, no "we're so excited". No trailing periods in texts/UI lines (occasional "!" ok). Persuasive but not crass: mix community + money, don't lead with money. Name the neighborhood ("12 Northside neighbors…"); "neighbors" fine, never a vague "your neighbors". Now and then invite spreading it ("got one, or know someone who might?"). Never "gathering dust"-style cutesy lines.
- Terms: "owner" (lists, gets paid) and "customer" (rents, pays). Never "renter" in copy or new code names. Customers "rent", owners "list". Fee is "15% fee (will stay low)", paid by the owner out of the rent, charged from day one; customers never see a fee line; a free rental (owner waived) has no fee or tax.
- Brand: cream `#F5F3EE`, ink `#1E3A2B`, orange `#FF4F00`, Helvetica Neue; 👋 Lendo logo. Tokens in `public/app.css`.
- Verify: `npm run typecheck`, then `npm run dev` + walk the flow (list → rent → YES via `/webhooks/blooio` → pickup → return → rate).
- Item names/descriptions: name the brand (+ model) when visible AND it matters to a customer (electronics, cameras, power tools, appliances, audio, bikes, fitness, baby gear, designer fashion, outdoor brands); leave it out for commodity items (folding chairs, ladders, hammers, sleds). Never guess a brand. Descriptions = 1-2 lines of checkable facts (model, key spec, what's included, visible condition), no filler. Rules live in `src/lib/identify.ts`.
